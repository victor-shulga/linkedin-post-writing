# LinkedIn Post Process

A 9-step method for turning **one idea** into a publish-ready LinkedIn post that
sells by being read: a hook stops the scroll, the body delivers one sharp lesson,
the formatting keeps it scannable.

Flow: **idea → 1 post type → 2 format → 3 angle → 4 meat+problem → 5 body (angle
drives the framework) → 6 summary → 7 trailer → 8 humanize → 9 layout.**

This is a **collaborative draft, not a one-shot generation.** Work step by step
and check in with the user between steps — fold each correction in and reprint
only the affected part.

## Before you start — collect the writer's context

The post must sound like the **user**, written for **their** audience. Collect
(ask once, then reuse for the whole session):

- **Audience / ICP** — who they write for and what that reader struggles with.
- **Voice sample** — 1–3 of the user's own past posts (or a few lines they wrote).
  Imitate its rhythm, vocabulary, and formality. If none is given, write plain,
  direct, human — a practitioner with scars, not a consultant with slides.
- **Language** — ask if unclear; default to the language of the idea/voice sample.
- **Address** — keep the second person consistent and respectful (in Ukrainian use
  «ви», never «ти»). First-person "I" narration is good, especially for personal posts.
- **Proof bank** — real numbers and lived experience the user can cite (years in
  the field, results, deals, failures). Concrete beats abstract — use what they give you.

> If the user has a personal-context or voice skill of their own (e.g. an
> `about-<name>` skill), read it first and let it override these defaults.

## Step 1 — Post type (expert vs personal) — ASK THIS FIRST

The single biggest fork. Ask (or infer): is this an **expert** post or a
**personal** post? It changes the format menu, angle list, tone, and CTA.

| | **Expert post** | **Personal post** |
|---|---|---|
| Goal | authority + lead-gen for the ICP | trust, relatability, the human side ("know / like") |
| Format (Step 2) | any of the 7 | **text-only OR text + 1 photo only** |
| Angle (Step 3) | expert content angles | personal themes |
| Voice | practitioner who teaches | more vulnerable, first-person, a real scene/emotion |
| Framework (Step 5) | angle drives it (PAS / structure) | narrative-first — **BAB** by default; PAS for an unpopular opinion |
| Meat (Step 4) | the lesson / system you teach | the insight FROM the story; substance = story + one takeaway |
| CTA | lead-gen / hand-raiser / save-and-check | soft — a reflective question; never "book a call" |

Lock the type before moving on — everything downstream branches from it.

## Step 2 — Format (the carrier)

Decide HOW the post is delivered. This sets length, CTA shape, and which visual
to produce after the copy is locked.

**Personal post →** offer only:
→ text-only
→ text + 1 photo (a real photo — behind-the-scenes, the person, the moment)

**Expert post →** full menu (ask, or infer — pasted an infographic → infographic):
→ poll (native poll: short text + 2–4 options)
→ text-only
→ text + 1 image (one simple visual or screenshot)
→ lead-magnet (post drives to a resource: comment-to-get / link; CTA = download)
→ infographic (single image — produce the visual after copy)
→ carousel (multi-slide PDF — produce the slides after copy)
→ screenshot / social-proof (post built around a screenshot: review, result, DM)

The text pipeline is the same for all. For **infographic / carousel**, the meat
(Step 4) ALSO becomes the cards/slides — lock the copy here first. For
**lead-magnet / poll**, the CTA and ending change.

## Step 3 — Angle (the lens)

Pick the genre/lens BEFORE writing. **Recommend the top 2–3** that fit the idea +
type + format (one-line rationale each); the user picks one or a combo. The angle
is a different axis from the copywriting framework (genre vs argument flow), and
it **drives Step 5**.

**Expert angles:**

| Angle | What it is | Fits when the meat is… | Drives |
|---|---|---|---|
| How-To | teach a process / answer a buyer's question (steps) | a practical method, steps | structural |
| How-I | YOUR process — how *you* did it | your own approach / experience | structural + personal |
| Lessons Learned | lessons from a career, role, or experience | takeaways from experience | argument → PAS/BAB |
| Mistakes | common mistakes + an "open loop" | what NOT to do | argument |
| Villain / status quo | attack a bad practice / challenge a norm | a contrarian thesis | argument → PAS |
| Framework | a named model or concept | your unique system | structural |
| Personal story | your journey / a defining moment | a personal story | structural → BAB |
| Case study | a client result, before → after | proof / social proof | structural → BAB |
| Bold statement | one sharp contrarian claim | a single strong statement | short |

Situational / advanced: Listicle, Dialogue, Featuring others / Piggyback, Poll /
Comment-bait, Promotion / Hand-raiser, Repurposing.

**Personal themes** (use as a prompt list for personal posts):
→ My path to a result
→ A defining moment
→ How I overcame a hard obstacle
→ Mistakes and lessons I learned
→ Behind the scenes
→ Reflecting on an achievement
→ My vision of the future
→ What I wish I'd known earlier
→ The hidden side of success
→ A crossroads (a moment of choosing a path)
→ My unpopular opinion
→ The moment I almost gave up
→ A mentor who changed everything
→ My biggest professional failure
→ A decision I'd make differently
→ The day everything changed
→ What nobody tells you about [your field]
→ A fear I finally overcame
→ A skill I underrated for years
→ Why I said "no" to a "great" opportunity
→ What my biggest client taught me
→ From burnout to clarity

## Step 4 — Meat + Problem

Lock the substance, articulated to fit the chosen type + format + angle.

- **Key thought:** the one sentence the whole post hangs on. Sharpen it until it bites.
- **Problem:** the painful, specific situation the reader is in (expert), or the
  tension/stakes in the story (personal).
- **Meat:** what you teach/show/offer (expert) — or the insight the story earns (personal).

For infographic/carousel formats, the meat is ALSO the cards/slides content. Lock
meat + problem with the user before writing the body.

## Step 5 — Body (the angle drives the framework)

Write the body anchored to the Step 3 angle — **don't default to PAS/BAB/AIDA for
everything.**

- **Structural angles** (How-To, How-I, Framework, Listicle, Dialogue, Case
  study): the angle IS the structure — steps / your-process narrative / the named
  model / a numbered list / before→after. Write **2 variants that differ in
  framing**, not a forced copywriting framework.
- **Argument angles** (Villain, Lessons Learned, Mistakes, Bold statement): rank
  the top fits among **PAS** (Problem–Agitate–Solution), **BAB**
  (Before–After–Bridge), **AIDA** (Attention–Interest–Desire–Action), one line
  each, and write a body variant per framework.
- **Personal posts:** narrative-first. **BAB** is the default (where I was →
  turning point → where I am / the lesson). PAS for an unpopular opinion. Lead
  with a real, specific scene, not a thesis.

Keep variants in the user's voice. The meat does NOT change with the framework —
only delivery and order. Don't finalize the hook yet (that's Step 7). Let the user
pick one variant or mix.

## Step 6 — Summary (INTERNAL — do not show)

Craft the closing so it (1) reinforces the message, (2) leaves an impression,
(3) inspires action, often ending on a line that pulls comments. Bake a strong
ending into the body — do **not** present "the summary" as a separate deliverable.

## Step 7 — Trailer (hook + re-hook)

The trailer is the first ~3 lines: **hook → blank line → re-hook**. Two jobs:
stop the scroll, and make the reader tap "more". Analyze what would land
(concrete numbers, "you're doing it wrong" tension, a costly self-told lie, a
blunt question; for personal — a raw, specific opening line) and present **5 hook +
re-hook combos**, each labeled with its angle, with a recommendation. Keep the
address consistent. Watch for the hook duplicating the body's closing line — flag it.

Keep re-hooks short. If a re-hook runs long, offer 3–5 tighter rewrites.

## Step 8 — Humanize (polish, remove AI patterns)

Strip AI tells while keeping the user's voice. Defaults that come up every time:

- **AI tells to cut:** significance-inflation ("in today's fast-paced world"),
  clichés, hedging, water, over-formatting, "not just X but Y", forced rule-of-three,
  sycophantic tone, empty transitions.
- **Em dashes ("—"):** easy to overuse. Keep 1–2 where they earn a pause (often in
  the hook); convert the rest to periods, colons, or short sentences.
- **Rhythm:** break even paragraphs into short punchy lines next to longer ones.
- Keep first person and opinion where it adds a pulse. Don't sand off the voice.

> If the user has a dedicated de-AI / anti-copywriting skill, run the draft through
> it here instead of (or on top of) these defaults.

Report the diagnostic briefly (language, AI density, top category) and what you
changed — don't dump a full audit unless asked.

## Step 9 — Layout / formatting

**Formatting is NOT optional and NOT light.** Format aggressively by DEFAULT, the
way the worked example below is formatted. A wall of equal-length sentences is a
fail, even if every sentence is short. The shape on screen matters as much as the words.

**Hard rules — apply every time:**

1. **One idea per line, blank line between almost every line.** Most "paragraphs"
   are a single line. The post should look mostly like whitespace with text floating
   in it. Two-line paragraphs are the max; three+ is a wall — break it.

2. **Any 3+ parallel items → a bullet list, as a "fir-tree".** Don't leave parallel
   points as inline sentences or flat lines. Convert to a list AND order the lines
   **by length, shortest → longest**, so the block forms a fir-tree. Marker: `→`
   (default) at the start of each line, lowercase, no trailing period. Intro the
   list with a line ending in a colon.

3. **Ragged rhythm — the one most often missed.** Alternate deliberately: a
   long-ish sentence, then a 1–3 word punch line on its own. Single-word/short
   lines are the rhythm. If three lines in a row are the same length, you've failed
   rule 3 — break one.

4. **Numbered lists (1. 2. 3.)** only for true sequential steps; parallel items use
   the `→` fir-tree, not numbers.

5. Keep the trailer (hook / blank / re-hook) as three separate lines at the very top.

**Worked example (this exact shape is the target — match it):**

```
The best code no longer wins clients.

In 2026 the winner is whoever has a sales system.

Everyone else discounts.            ← one-line punch (rhythm)

In 4 years the market under agencies flipped:   ← colon intro

→ 25% more agencies                  ← fir-tree: short → long, "→", no period
→ cost per lead up 2–3×
→ half as many dev openings as in 2022

The war for the client got real.    ← punch line after the list

Audit your own agency.              ← short command line before the CTA question

Which step has the biggest hole for you?
```

**Self-check before saving** — read the draft as a SHAPE: is it mostly whitespace?
are parallel points fir-trees (short→long, `→`)? is there a 1–3 word punch line every
few lines? are there any 3 equal-length lines in a row (fix them)? If any answer is
no, reformat before presenting.

Then save the final post as a `.md` file and present it. Keep counts consistent:
if a number appears in the body, update every mention when the list changes.

## Output discipline

- Between steps, show only what the user needs to decide on — don't over-explain.
- When the user edits, reprint the affected block, not the whole post, unless asked.
- The final deliverable is one clean, publish-ready post in the user's language,
  addressed consistently, formatted per Step 9. For infographic/carousel formats
  (Step 2), also produce the visual once the copy is locked (use a visual skill if
  one is installed, otherwise output the slide/card outline).
